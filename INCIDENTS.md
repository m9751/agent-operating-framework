# Incident Log

Every rule in this framework was born from a real failure. This log is the source of record.

Each row shows the incident, the lesson, and the rule it hardened. Dates are month-precision. Names of systems, accounts, and employers have been genericized — the failures are the point, not the forensics.

| 2 | 2026-03 | Entire session spent chasing the wrong hypothesis about a crash. Reading 43 lines of config found the real problem in 2 minutes. | Acting without reading wastes hours. Over an hour of session time burned. | If a tool exists to check it — `--help`, `curl`, schema query — use it. | 26 | 2026-05 | The framework's README claimed "rules that can't be ignored" while shipping six rules where only three had `## Enforcement` sections and only three had backing hooks. Adopters were sold enforcement that did not exist. | Publish a rule-to-hook coverage matrix. Recast marketing language to match the matrix. Never describe a prose rule as non-bypassable unless a blocking hook exists for that rule. | [AGENT_FRAMEWORK.md §5.3](AGENT_FRAMEWORK.md) |
| 27 | 2026-05 | The framework defined hooks as the strongest enforcement tier, then said hooks should fail-open universally on error. That collapses the barrier on degraded paths — the control disappears exactly when the enforcement mechanism is unhealthy. | Classify hooks by blast radius. Destructive and security hooks default to fail-closed; advisory hooks fail-open. Every shipped hook declares both attributes in its header; CI rejects un-annotated hooks. | [AGENT_FRAMEWORK.md §5.2](AGENT_FRAMEWORK.md) |
| 28 | 2026-05 | Section 0.5 ("ask focus before any work") and Section 1.3 ("just fix it on a bug report") contradicted directly. Read literally, the framework demanded both confirmation and autonomy on the same request. | Define precedence explicitly. §0.5 Step 3 applies when intent is ambiguous; an explicit bug report or named-target request IS focus confirmation. Tie-break to autonomy, not confirmation. | [AGENT_FRAMEWORK.md §1.3](AGENT_FRAMEWORK.md) |
| 29 | 2026-05 | A categorical "MANDATORY: never build local persistent infrastructure" rule encoded one operator's preference (consumer SaaS workflow, low operator availability) as universal law. | 30 | 2026-05 | Onboarding guides referenced 8 rule filenames that no longer existed after a consolidation pass. | 31 | 2026-05 | `secure-configuration` rule documented "never paste API keys / tokens / passwords in chat" and "never overwrite shared config files," but nothing enforced either invariant. The rule was advisory by gap, not by design — the failure modes were hookable. | Move enforcement to the hook layer. | 32 | 2026-05 | `session-lifecycle` Phase 1 mandated focus confirmation before any task, but had no enforcement. The agent could fire Edit/Write/Bash before the operator named focus, sometimes despite §1.3 precedence applying ("explicit named-target requests count as confirmation"). The rule was advisory; the framework's own escalation ladder said it should be a hook. | Two-script pair: `UserPromptSubmit` writer detects explicit-task patterns and writes a session breadcrumb; `PreToolUse` gate fires advisory warning when first Edit/Write/Bash runs without a breadcrumb. Fail-open by design — §1.3 explicitly rejects the friction of hard-blocking the first action. | [focus-breadcrumb.sh](examples/hooks/focus-breadcrumb.sh) + [focus-confirmation-gate.sh](examples/hooks/focus-confirmation-gate.sh) |
| 33 | 2026-05 | `scope-discipline` Gate 5 (Dormant Code Check) mandated grepping for callers before any remediation plan, but had no enforcement. | 34 | 2026-05 | A breadcrumb library used an undocumented env var (`CLAUDE_SESSION_ID`) as its primary session key. | 35 | 2026-05 | A watcher hook auto-pushed to a branch-protected repo and logged `PUSH-FAIL` approximately every 30 seconds for ~14 days. The watcher continued running — it committed locally on each cycle and then failed push — so there was no crash to notice. Discovered only during an unrelated hook audit. | Watcher-class hooks that auto-push to a protected branch must use the `PUSH-SKIPPED` pattern: keep the commit step (local backup), skip the push step, log `PUSH-SKIPPED branch-protection-active`, and document the manual PR step. Without telemetry on hook fires, this class of silent degradation is undetectable. | [`guides/hook-operations.md`](guides/hook-operations.md) + `# fail-mode: silent-skip` taxonomy tier |
